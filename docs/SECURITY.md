## Pontos conhecidos (aceitos por enquanto)

- **Mídia pública**: avatares e tokens não exigem login; as URLs têm UUID (não adivinháveis).
- **Histórico de rolagens em memória**: some quando a API reinicia; vai para o banco junto com o chat.
- **Sem CSP no site**: o Next em desenvolvimento usa scripts inline; adicionar uma Content-Security-Policy no deploy de produção.
- **Dependências de desenvolvimento**: `npm audit` aponta 7 avisos moderados no `minimatch` usado pelo typescript-eslint (só lint, não vai para produção). Produção: 0 vulnerabilidades.
- **Limites em memória**: o limitador de tentativas e o de rolagens vivem no processo; com mais de uma instância da API, trocar por um store compartilhado (ex.: Redis).

- **Socket aberto após reset de senha pelo CLI**: o `setPassword` revoga as sessões HTTP, mas um socket já conectado só cai quando reconectar (o logout pela tela derruba na hora). Revalidar a conta a cada `roll:request` se isso virar problema.
- **Campos livres para o jogador**: atributos, bônus de CA dos itens e Aberturas são editáveis pelo jogador, como no Roll20. Classe, nível e máximos são só do Mestre.
- **Senha por argumento no CLI**: `account:password -- "<login>" <senha>` deixa a senha no histórico do shell; prefira a senha gerada.
- **Edição simultânea fora dos campos do Mestre**: quando Mestre e jogador editam a mesma ficha ao mesmo tempo, a aba do jogador aplica os campos do Mestre (classe, nível e máximos) sobre o rascunho e a aba do Mestre mantém o rascunho dele; nos demais campos vence o último a salvar. O servidor checa a versão antes das permissões (409 antes de 403) e grava ancorado na versão lida do banco.
